# gage-ffi

Swift and Kotlin bindings for `gage-core`, generated by UniFFI
([ADR-0060](../../doc/decisions/0060-mobile-bindings.md)). Not published to
crates.io; the iOS app consumes the build's output.

## Building for iOS

You need macOS with Xcode (the command line tools alone are not enough:
the build needs `xcodebuild` and the simulator) and the two Rust targets:

```sh
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
make xcframework
```

That writes, under `target/ios/`:

- `GageFFI.xcframework`: a device slice and an arm64 simulator slice of
  the static library, with the C header and module map
- `swift/gage_ffi.swift`: the generated Swift, from the same UniFFI as the
  library so it can't drift. It is not committed.

The deployment target is iOS 18.0 for every slice, C objects included; the
script fails if any object claims a newer minimum. Apps link the framework
with `-liconv` and the `Security` and `CoreFoundation` frameworks.

iOS and Android build without SSH, so an SSH remote is refused with a
pointer to HTTPS ([ADR-0062](../../doc/decisions/0062-no-ssh-on-mobile.md)).

## Smoke test

```sh
make ios-smoke
```

Writes a vault with `examples/smoke_fixture.rs`, builds
`tests/swift/main.swift` against the XCFramework, and runs it in a
throwaway iOS simulator (created and deleted by the script). It opens,
unlocks and lists, and checks the wrong-passphrase and unknown-vault
errors. CI runs both targets in `.github/workflows/mobile.yml`.
