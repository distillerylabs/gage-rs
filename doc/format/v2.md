# gage on-disk format, version 2

This is the normative specification of everything gage-rs writes to disk,
or reads back, that outlives one process. It covers two kinds of storage:

- **A vault.** It is committed and shared through git, and any git writer
  can edit it.
- **The local state** of one device. It is never committed.

The [golden v2 vault](../../tests/fixtures/format-v2/README.md) is a
complete example of this document. The `format_v2_*` tests check this
document against the code that defines each artifact. How this document
changes is in [README.md](README.md).

The key words MUST, MUST NOT, SHOULD and MAY are to be read as in
[RFC 2119](https://www.rfc-editor.org/rfc/rfc2119). "A reader" is any code
that reads an artifact. "A writer" is any code that creates or rewrites
one.

**Not part of the format:**

- help text and error wording
- exit codes ([doc/cli/exit-codes.md](../cli/exit-codes.md))
- the enrollment code's spelling, which a human types and which is never
  stored
- the exact bytes of TOML and YAML. Whitespace, quoting and scalar style
  are the writer's choice. This document fixes names, structure, types,
  and the order where it says so.

## 1. Common rules

- **Text** is UTF-8. TOML files are TOML 1.0.
- **age** means the [age v1 format](https://age-encryption.org/v1).
  Recipients are X25519 (`age1…`), and identities are `AGE-SECRET-KEY-1…`.
- **Timestamps** are RFC 3339. A writer writes UTC with a `Z` suffix at
  whole-second precision unless a section says otherwise. A reader MUST
  accept any RFC 3339 offset.
- **Atomic writes.** Every file a writer replaces is written to a
  temporary file in the same directory and renamed into place. A reader
  never sees a truncated file.
- **Modes** are given for Unix. On Windows they are not applied.
- **Untrusted input.** Everything in a vault is untrusted: any git writer
  can change it. A vault id or device name read from a vault becomes a
  local path component only after it passes the validation in
  [section 4](#4-identifiers).

Defined in: `crates/gage/src/atomicfile.rs`, `crates/gage/src/entry/mod.rs`
(`Timestamp`).

## 2. The vault

### 2.1 Layout

```
<vault>/
  .gage/config.toml        control plane: id, type, method default, recipients
  .gage/pending/           enrollment requests (may be absent)
  .age-recipients          recipient public keys, one per line
  .gitattributes
  .gitignore
  entries/<uuid>.age       one file per entry
```

- Nothing else in a vault is gage's.
- A writer MUST NOT encode anything about an entry's contents in a path.
  Entry and request filenames are random UUIDs.
- A vault is a git repository whose working tree root is `<vault>`.
- `entries/` and `.gage/pending/` may be absent. Git doesn't track empty
  directories, and a reader treats an absent directory as empty.

Defined in: `crates/gage/src/vault.rs` (`Vault::create`, `create_layout`).

### 2.2 `.gage/config.toml`

Plaintext control-plane data, committed. Mode `0644`.

```toml
[vault]
name = "personal"
id = "ff336b5e-3a36-4164-a014-1b6890bb9785"
type = "git"
format_version = 2
created = "2026-10-28"

[method]
default = "passphrase"

[[recipients]]
device = "laptop-1"
pubkey = "age1yrmhdexp2nu9m4ty3m7s8yyupyv5kdcgkwxce9nkr82jycnmde6qxph5l3"

[[recipients]]
device = "recovery-paper-key"
pubkey = "age1g6ltwxkauxtfhedctepamjta92w5cteyxe0zuxju4twpaleleamsjjgs30"
```

| Key | Type | Required | Meaning |
|---|---|---|---|
| `vault.name` | string | yes | The name given at `init`. Informational: each device names the vault locally (see [3.2](#32-the-global-configtoml)). |
| `vault.id` | string | yes | The vault id ([4](#4-identifiers)). It is minted once, by `init`, and never changes. |
| `vault.type` | string | yes | `"git"`, the only type. |
| `vault.format_version` | integer | yes | `2` for this document. |
| `vault.created` | string | yes | The UTC creation date, `YYYY-MM-DD`. |
| `method.default` | string | yes | The identity method suggested to devices joining. Only `"passphrase"` is defined. It is a default, not a constraint: each device's own method is local ([3.2](#32-the-global-configtoml)). |
| `method.plugin` | string | no | Reserved for a plugin method. Omitted when empty. |
| `recipients` | array of tables | yes | Every recipient, in the order of `.age-recipients`. |
| `recipients[].device` | string | yes | A device name ([4](#4-identifiers)). |
| `recipients[].pubkey` | string | yes | An age X25519 recipient. |

- A recipient carries only `device` and `pubkey`. A writer MUST NOT
  record a per-recipient method, which would tell anyone with read
  access which recipient is the softest target.
- Device labels are unique within a vault.
- **`recovery-paper-key`** is a reserved label. It names the vault's
  offline recovery recipient. A device MUST NOT take that name, and at
  most one recipient holds it.

A reader MUST check, in this order, and act on nothing in a file that
fails a check:

1. `format_version` is exactly `2`. An absent key reads as `0`. Any other
   value is refused, never parsed best-effort. The refusal says whether
   the file is older (re-create the vault) or newer (upgrade gage).
2. `vault.id` is a valid vault id.
3. Every `recipients[].device` is a valid device name.

Defined in: `crates/gage/src/vaultconfig/mod.rs`, `vaultconfig/id.rs`,
`crates/gage/src/devicename.rs`, `crates/gage/src/recovery/mod.rs`
(`RECOVERY_DEVICE_LABEL`).

### 2.3 `.age-recipients`

- One age recipient per line, each line newline-terminated. Mode `0644`.
- No header and no comments, so a stock `age -R .age-recipients` can use
  the file directly.
- A writer writes the keys of `.gage/config.toml`'s `recipients`, in the
  same order.
- A reader MUST skip blank lines and trim surrounding whitespace. An
  absent file is an error, not an empty list.
- The two recipient files MUST name the same set of keys. When they
  differ, a reader MUST NOT encrypt to either list. It reports the
  difference instead, and `recipient verify --repair` rewrites
  `.age-recipients` from `config.toml`.

Defined in: `crates/gage/src/recipients.rs`, `crates/gage/src/recipient.rs`
(`verify_recipients`), `crates/gage/src/trustcache.rs`
(`require_recipients_in_sync`, `repair_recipients`).

### 2.4 `.gitattributes` and `.gitignore`

Written by `init`, exactly:

```
# .gitattributes
.age-recipients -merge
.gage/config.toml -merge
```

```
# .gitignore
.DS_Store
Thumbs.db
```

`-merge` makes any divergence in either recipient file a conflict for a
human, never a line merge.

Defined in: `crates/gage/src/vault.rs` (`GITATTRIBUTES`, `GITIGNORE`).

### 2.5 `entries/<uuid>.age`

- One file per entry, named by the entry id, a lowercase hyphenated
  UUIDv4 (`entries/38149e3b-….age`).
- The filename carries no meaning beyond identity.
- Each file is an age file encrypted to every key in `.age-recipients`.
  Its plaintext is the entry payload ([2.6](#26-the-entry-payload)).
- Mode `0600`. The `entries/` directory is `0700`.
- A reader MUST ignore anything in `entries/` that is not a file named
  `<uuid>.age`.

Defined in: `crates/gage/src/entry/mod.rs` (`ENTRIES_DIR_NAME`,
`ENTRY_FILE_EXT`), `crates/gage/src/entry/store.rs`.

### 2.6 The entry payload

One YAML mapping, the plaintext inside the age layer:

```yaml
title: github
description: work account
created: 2026-10-28T05:56:12Z
updated: 2026-10-28T05:56:12Z
updated_by: laptop-1
value: fixture-not-a-secret
fields:
  url: https://github.com/login
  username: octo-fixture
x-future-map:
  rotate: true
  tags:
    - "a"
    - "b"
x-future-plain: 0x1F
```

| Key | Type | Required | Meaning |
|---|---|---|---|
| `title` | string | yes | What `ls` shows and queries match. |
| `description` | string | no | Omitted when empty, never written as null or `""`. |
| `created` | timestamp | no | Set once, at insert. |
| `updated` | timestamp | no | Rewritten on every edit. |
| `updated_by` | string | yes | The device name of the last writer. |
| `value` | string | yes | The primary secret, or a note's body. |
| `fields` | mapping of string to string | no | Structured fields. Omitted when empty. |
| any other key | any YAML value | no | Unknown to this version: see below. |

**Writing.**

- A writer emits the keys in the table's order, then the unknown keys
  sorted by name. `fields` are sorted by name.
- Timestamps are unquoted RFC 3339 scalars, UTC, whole seconds.
- Every string MUST read back exactly as written, newlines, tabs and
  leading or trailing whitespace included. A writer MUST verify this by
  parsing its own output, and refuse to write text that doesn't round-trip.

**Reading.** A reader MUST:

- read every scalar under a string key as that string. `title: 0x1F` is
  the string `0x1F`, never resolved to a number.
- **keep every unknown key and its value**, and write them back
  unchanged on the next edit. An unknown key is not an error. This is how
  an entry written by a newer gage survives an edit by an older one.
- refuse:
  - a mapping or sequence where a string belongs
  - a `fields` value that is not a scalar
  - a duplicate key
  - more than one YAML document
  - a top level that is not a mapping
  - text that is not UTF-8
- skip a leading byte-order mark.
- read an empty document, or a bare null, as an entry with every field
  empty.

Defined in: `crates/gage/src/entry/mod.rs` (`Entry`, `Extra`,
`Timestamp`), `crates/gage/src/entry/yaml.rs` (`marshal`, `unmarshal`).

### 2.7 `.gage/pending/<id>-<expiry>.age`

An enrollment request: a new device asking to be added as a recipient.

**Filename.** `<request-id>-<expiry>.age`:

- `request-id` is a lowercase hyphenated UUIDv4.
- `expiry` is the expiry instant in decimal Unix seconds.

A reader decides from the filename alone, without decrypting, which
requests are live:

- A name that doesn't parse is not a request. A reader MUST leave it
  alone.
- A file larger than 16 KiB is skipped.
- A request is live while `now < expiry <= now + 7 days`. An expiry past
  that ceiling is treated as expired.
- Expired requests are deleted by the next recipient write, in its
  commit.

**Contents.**

- An age file encrypted to one scrypt recipient. Its passphrase is the
  normalized enrollment code: 80 random bits, in a spelling defined by
  the CLI, not here.
- A writer seals at work factor 14.
- A reader MUST refuse a claimed work factor above 18 before running any
  KDF. Any git writer can put a file in `pending/`.
- The plaintext is TOML:

```toml
request_id = "f61694fd-e69d-4d65-ab67-371884a7fce5"
vault_id = "ff336b5e-3a36-4164-a014-1b6890bb9785"
device = "phone-1"
pubkey = "age1…"
method = "passphrase"
created = "2026-10-28T05:56:13Z"
expires = "2026-10-29T05:56:13Z"
```

Every key is a required string. A reader MUST refuse the request when:

- `request_id` or `vault_id` is not a valid id
- `device` is not a valid device name
- `pubkey` is not an age recipient
- `method` is not one this build performs
- `created` or `expires` is not RFC 3339
- `request_id` differs from the filename's id
- `vault_id` differs from the vault's
- `expires` is before `created`
- `expires` is not live, by the rule above

The default lifetime is 24 hours, and the maximum is 7 days. A reader
refuses to try a code against more than 32 requests at once.

Defined in: `crates/gage/src/enrollment/mod.rs`
(`PENDING_DIR`, `MAX_PENDING_REQUEST_BYTES`, `MAX_ENROLLMENT_TTL`,
`MAX_ENROLLMENT_ATTEMPTS`), `enrollment/name.rs`, `enrollment/seal.rs`
(`Payload`, `validate_payload`), `crates/gage/src/crypt.rs`
(`SHIPPED_ENROLLMENT_SCRYPT_WORK_FACTOR`,
`ENROLLMENT_SCRYPT_MAX_WORK_FACTOR`).

### 2.8 Git: branch, remote, author, commits

- **Branch:** `main`.
- **Remote:** `origin`.
- **Author and committer** of every commit gage makes:
  `gage <gage@localhost>`.
- A commit message names no entry and carries no plaintext.

| Operation | Message | Parents |
|---|---|---|
| `init` | `gage: initialize vault` | 0 |
| insert, edit, rm, rename | `<entry-uuid>`, the id of the one entry file it changes | 1 |
| mv, cp to another vault | `<new-entry-uuid>` in the destination; for mv, then `<old-entry-uuid>` in the source | 1 |
| `recipient add` | `gage: recipient add <device> (reencrypt)` | 1 |
| `recipient remove` | `gage: recipient remove <device> (reencrypt)` | 1 |
| `recipient approve` | `gage: recipient approve <device>[, <device>…] (reencrypt)` | 1 |
| `recipient deny` | `gage: enrollment request denied` | 1 |
| approving a request that is already a recipient | `gage: enrollment request cleared (already a recipient)` | 1 |
| `recipient verify --repair` | `gage: recipient repair` | 1 |
| `identity enroll` | `gage: enrollment request` | 1 |
| `recovery enroll` | `gage: recovery enroll <device>, retire recovery-paper-key (reencrypt)` | 1 |
| `recovery rotate` | `gage: recovery rotate (reencrypt)` | 1 |
| sync, disjoint changes | `gage: merge origin` | 2 |
| sync, entry conflicts resolved | `gage: merge origin, resolving <n> entry` or `…<n> entries` | 2 |

The init commit holds exactly `.age-recipients`, `.gage/config.toml`,
`.gitattributes` and `.gitignore`.

Defined in: `crates/gage/src/gitrepo/mod.rs` (`INITIAL_BRANCH`, `ORIGIN`,
`AUTHOR_NAME`, `AUTHOR_EMAIL`), `crates/gage/src/vault.rs`
(`INIT_COMMIT_MESSAGE`), `crates/gage/src/entry/crud.rs`,
`crates/gage/src/movecopy.rs`, `crates/gage/src/recipient.rs`,
`crates/gage/src/enrollment/approve.rs`, `enrollment/enroll.rs`,
`crates/gage/src/trustcache.rs`, `crates/gage/src/recovery/swap.rs`,
`crates/gage/src/remotesync.rs` (`MERGE_COMMIT_MESSAGE`),
`crates/gage/src/syncresolve.rs` (`resolution_message`).

## 3. Local state

### 3.1 Roots

| Root | `XDG_*` variable (wins on any OS) | Unix default | Windows default |
|---|---|---|---|
| `$GAGE_CONFIG` | `XDG_CONFIG_HOME` | `~/.config/gage` | `%APPDATA%\gage` |
| `$GAGE_DATA` | `XDG_DATA_HOME` | `~/.local/share/gage` | `%LOCALAPPDATA%\gage` |
| `$GAGE_STATE` | `XDG_STATE_HOME` | `~/.local/state/gage` | `%LOCALAPPDATA%\gage\state` |

- macOS uses the Unix layout.
- A vault's default location is `$GAGE_DATA/vaults/<name>`.
- Everything a device stores about a vault is keyed by the **vault id**,
  never by its local name.

Defined in: `crates/gage/src/xdgpaths.rs`, `crates/gage/src/paths.rs`.

### 3.2 The global `config.toml`

`$GAGE_CONFIG/config.toml`, mode `0600`, in a `0700` directory. It lists
the vaults this device knows:

```toml
current = "personal"

[vaults.personal]
path = "/home/you/.local/share/gage/vaults/personal"
id = "ff336b5e-3a36-4164-a014-1b6890bb9785"
type = "git"
device = "laptop-1"
pubkey = "age1yrmhdexp2nu9m4ty3m7s8yyupyv5kdcgkwxce9nkr82jycnmde6qxph5l3"
method = "passphrase"

[vaults.personal.git]
origin = "https://github.com/you/personal-vault.git"

[shell]
prompt = "{vault}{lock} fixture> "
idle_timeout = "15m"
history_file = "$GAGE_STATE/history"
clipboard_timeout = "1m30s"
```

| Key | Type | Required | Meaning |
|---|---|---|---|
| `current` | string | no | The default vault's name. Omitted when unset. |
| `vaults.<name>` | table | no | One per registered vault. `<name>` is the local name: one plain path component. |
| `….path` | string | yes | The vault's working tree. |
| `….id` | string | yes | A copy of the vault's `[vault].id`. A reader MUST refuse a vault whose committed id differs. |
| `….type` | string | yes | `"git"`. |
| `….device` | string | yes | This device's name in that vault. |
| `….pubkey` | string | no | The public key this device holds for that vault. |
| `….method` | string | yes | How this device unlocks that vault: `"passphrase"`. |
| `….git.origin` | string | no | The remote URL. |
| `shell` | table | no | Session preferences. Every key is optional. |
| `shell.prompt` | string | no | Prompt template, with tokens `{vault}`, `{lock}` and `{dirty}`. |
| `shell.idle_timeout` | duration | no | Default `10m`. `0` disables re-locking. |
| `shell.history_file` | string | no | Default `$GAGE_STATE/history`. `$GAGE_CONFIG`, `$GAGE_DATA`, `$GAGE_STATE` and a leading `~` are expanded. |
| `shell.clipboard_timeout` | duration | no | Default `45s`. Minimum `1s`. |

**The duration grammar** is Go's `time.ParseDuration`:

- an optional sign, then one or more `<decimal><unit>` terms (`1h30m`,
  `1.5h`), or a bare `0`
- units `ns`, `us`/`µs`, `ms`, `s`, `m`, `h`

A reader MUST refuse:

- a malformed duration, such as `10min`
- a negative one
- a `clipboard_timeout` below the minimum

A reader MUST NOT ignore a malformed value: a typo must not silently
disable a timeout.

Defined in: `crates/gage/src/config.rs`, `crates/gage-cli/src/shell.rs`
(`resolve`, `parse_duration`).

### 3.3 The identity file and `vault-name.txt`

`$GAGE_DATA/identities/<vault-id>/<device>.age`:

- mode `0600`, in a `0700` directory
- never committed or synced

It is an age file encrypted to exactly one scrypt recipient, the device's
passphrase. Its plaintext:

```
# created: 2026-10-28T05:56:11Z
# public key: age1yrmhdexp2nu9m4ty3m7s8yyupyv5kdcgkwxce9nkr82jycnmde6qxph5l3
AGE-SECRET-KEY-1…
```

- A writer writes this shape, with `created` in UTC at whole seconds.
- A reader MUST take the first line that begins `AGE-SECRET-KEY-1`, trim
  it, and ignore the rest.
- **scrypt.** A writer wraps at work factor 19.
  - A reader MUST refuse a claimed factor above 22 before running the KDF.
  - It MUST accept any factor at or below the cap. There is no floor, so
    raising the shipped factor needs no migration.
- **Errors.** A failed unwrap of a scrypt-only header is a wrong
  passphrase. Any other failure means the file is corrupt.

`vault-name.txt` sits beside it:

- one line, the vault's local name at the time the identity was created,
  newline-terminated
- mode `0600`
- a human-readable hint for a directory named by an id. Nothing reads it
  as truth.

Defined in: `crates/gage/src/identityfile.rs` (`MARKER_FILE_NAME`,
`format_identity_file`, `key_line`), `crates/gage/src/crypt.rs`
(`SHIPPED_SCRYPT_WORK_FACTOR`, `SCRYPT_MAX_WORK_FACTOR`),
`crates/gage/src/paths.rs` (`identity_file_path`).

### 3.4 The trust cache

The trust cache is two files in `$GAGE_STATE/<vault-id>/`, each mode
`0600`. Together they record the recipient list this device last
confirmed.

**`known-config.toml`** is a byte-for-byte copy of the vault's
`.gage/config.toml` as last confirmed.

**`trust.toml`:**

```toml
recipients_hash = "e3bd56c0…"
confirmed_at = 2026-10-28T05:55:38Z
mismatch_seen = "…"
```

| Key | Type | Required | Meaning |
|---|---|---|---|
| `recipients_hash` | string | yes | Lowercase hex SHA-256 of `.age-recipients`' exact bytes, as last confirmed. |
| `confirmed_at` | TOML offset datetime | no | When it was confirmed. |
| `mismatch_seen` | string | no | The `.age-recipients` hash of a mismatch already shown to the human. Omitted when empty. |

- A device with no cache trusts the vault's current state, then writes
  the cache.
- When the config bytes or the recipients hash differ from the cache, a
  write MUST stop and ask a human to review the change.

Defined in: `crates/gage/src/trustcache.rs` (`KNOWN_CONFIG_FILE`,
`TRUST_FILE`, `TrustRecord`), `crates/gage/src/paths.rs`
(`trust_cache_dir`).

### 3.5 Lock, token and history files

- **`$GAGE_STATE/locks/<vault-id>.lock`** is the vault's advisory write
  lock.
  - Every write holds it across read, modify and commit.
  - The file's contents (`pid=<pid>\nsince=<RFC 3339>\n`) only describe
    the holder in a message. The lock itself is the OS file lock.
- **`$GAGE_STATE/tokens/<host>`** holds one HTTPS token, trimmed, mode
  `0600`.
  - `<host>` is the remote's host. It MUST be a single path component: no
    separator, NUL, colon or surrounding whitespace, and not `.` or `..`.
- **`$GAGE_STATE/history`** (or `[shell].history_file`) is the session's
  command history, one command per line, mode `0600`.

Defined in: `crates/gage/src/vaultlock.rs`, `crates/gage/src/remoteauth.rs`,
`crates/gage/src/paths.rs` (`lock_file_path`, `token_file_path`),
`crates/gage-cli/src/history.rs`.

## 4. Identifiers

**Vault id:**

- the canonical lowercase hyphenated form (8-4-4-4-12) of a non-nil UUID
- minted as a random UUIDv4
- A reader MUST refuse any other spelling: uppercase, braces, `urn:uuid:`
  or no hyphens. Two spellings of one id would give one vault two local
  state directories.
- Request ids and entry ids follow the same rule.

**Device name:**

- 1 to 63 characters from `a-z 0-9 . _ -`
- not made only of dots
- A reader MUST refuse any other name read from a vault before it builds
  a path from it.

**Vault name**, the local name only:

- one plain path component
- not empty, and with no `/`, `\` or NUL
- not `.`, `..`, or a drive prefix

Defined in: `crates/gage/src/vaultconfig/id.rs` (`valid_id`),
`crates/gage/src/devicename.rs` (`valid`), `crates/gage/src/vault.rs`
(`check_name`).
