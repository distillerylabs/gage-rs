# ADR-0015: SSH remotes: ssh-agent only

- Status: Accepted
- Origin: Q-SSH ([entry](../archive/rust-port/open-questions.md#q-ssh)); amends [ADR-0014](0014-git-crate.md)

## Decision

SSH remotes are supported at a best-effort level, through git2's `ssh`
feature (vendored libssh2) and ssh-agent only.

- Credentials come only from `Cred::ssh_key_from_agent`. gage reads no key
  files and asks for no passphrase.
- libgit2's exec-based SSH backend is never selected: it would shell out to
  `ssh`.
- An SSH host with no dot is treated as a `~/.ssh/config` alias and refused
  with the real reason, pointing at the HTTPS spelling and `gage auth
  login`. libssh2 does not read `~/.ssh/config` either.
- Host keys: libgit2 checks `~/.ssh/known_hosts` itself. gage installs no
  `certificate_check`, so an unknown or mismatched host fails closed with
  `ErrorCode::Certificate`.

## Consequences

- libssh2-sys is a second vendored C library, built from bundled source on
  all three OSes; `crates/gage` names it with `vendored-openssl` on Unix.
- Tests pin which path resolving the method took (an agent credential, or an
  error naming ssh-agent), never the outcome: no network or agent can be
  assumed.
- The supported remote auth path remains HTTPS + token.
